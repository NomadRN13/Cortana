2

Supabase — the database

free~20 min

→ supabase.com

This is the part that makes the app real. Without it every signup, match and message has nowhere to go.

  1. New project. Pick a strong database password and save it somewhere — you can't recover it. Region: us-east-1.
  2. Wait ~2 minutes for it to finish setting up.
  3. SQL Editor → New query. Open supabase/setup.sql from the repo, copy all of it, paste, and press Run. That's all 22 migrations — every table, every security rule, the matching engine.
  4. Authentication → Sign In / Up → Email: turn it on. Check the "Magic Link" template contains {{ .Token }} so the email carries a 6-digit code.
  5. Settings → API. Copy the Project URL and the anon public key.
Copy the key labelled "anon" / "public" only. The one below it, service_role, ignores every security rule in the database. The script in step 3 decodes what you paste and refuses that one rather than publishing it to your website — but don't rely on it.

Make yourself the moderator

free2 min
  1. Go to your-site/admin/ and sign in with your email. That creates your account.
  2. Supabase → SQL Editor → run this with your real address:
insert into admins (user_id)

Reload /admin and the desk appears: photo approvals, reports, events, and the Numbers tab with your waitlist and demo funnel.

Photos members upload stay invisible until you approve them here. Nobody can add themselves to this list through the app — the table is unreachable from the API by design.
6

Twilio — the text messages

~$1.15/mo + $0.008/text20 min

→ twilio.com

Signups stop dead at the phone step without this. It's the step that keeps fake accounts out, so it isn't optional for a dating app.

  1. Create an account, buy a US phone number.
  2. Note your Account SID and Auth Token, then create a Messaging Service, add the number to it, and copy its SID.
  3. Supabase → Authentication → Sign In / Up → Phone: enable, pick Twilio, paste all three. Leave "Phone confirmations" on.
  4. Test with your own number — the code should arrive in seconds.

Building the actual app

7

Expo — where the app gets built

free~20 min

→ expo.dev — create the account, then in a terminal:

npm install -g eas-cli
eas login
cd mobile
eas init
eas build --profile production --platform android

The build runs on Expo's machines, takes about 15 minutes, and produces an .aab file — the format Play wants.

Let EAS manage the signing key. Losing an app signing key means never being able to update the app under that listing again.
